# Offline task-execution baseline (issue 08)

Status: implemented as an offline library (`uzumaki.baseline`, `uzumaki.fixture_env`) exercised by `tests/test_baseline.py` inside `make check`. It uses a scripted fixture world, not a simulator, and no model. Acceptance of the issue is decided by independent validation and review, not by this note.

## Frozen plan

- **Workload:** the eight frozen `pick-place-v1` cases in `tests/fixtures/baseline_cases_v1.json` (`uzumaki.baseline-cases/1.0`): `nominal`, `unreachable-goal`, `failed-grasp`, `stale-observation`, `stale-after-pick`, `retry-exhausted`, `cancellation` and `worker-crash`. Each fixes geometry, injected faults (misgrasped picks, stale observes, a crashing call, goal withdrawal after a call) and the expected primary outcome, progress, lifecycle state, harness status, attempts and admitted pick/place counts. Skills are the hand-authored `tests/fixtures/skills_pick_place_v1.json`. Trial candidates are `tests/fixtures/candidates_pick_place_v1.json` (`hold-still`, `report-success`) plus a positive control the test builds from `pick-and-place` (`pick-place-candidate`, state `candidate`).
- **Inputs and environment:** Python 3.12.12, stdlib-only runtime, the pinned `requirements-dev.txt`. Fixture time is an integer-millisecond fake clock (case start 1000 ms; observe and abort 100 ms, pick and place 1500 ms; settle delay 200 ms; a stale observe lags 300 ms). Sockets are blocked, `RecordedProvider` construction fails during the suite, and `BoundedRun` has no model provider and a model-call budget of 0.
- **Correctness guards (`CORRECTNESS_CHECKS`):** for every frozen case, `correctness_failures(case, run)` must be empty. It checks that the bundle validates, the evaluator's primary outcome and progress, the lifecycle state, harness status, attempts used, admitted pick/place counts, zero invariant violations, zero model calls, and that the bundle's recorded outcome and terminal state equal the evaluator verdict and run report.
- **Containment guards:** the world decides admission itself (latest fresh observation within 200 ms, goal active and not aborted, reachable pose, held or not held). A request the harness should not send is rejected without effect, and violations count only admitted actuation that broke these conditions. Skill bodies may call only the tools their artifact permits; any other request raises `ToolNotPermitted` before anything is sent. Budgets are `BASELINE_BUDGETS`: 3 attempts, 120 s fixture wall time, 0 model calls, 40 tool steps, 4096 bytes per result and 65536 in total.
- **Metrics/thresholds:** pass/fail only. Every frozen case must pass every correctness check, and its recorded-decision replay must match the fresh run (`ReplayReport.matches`, no differences). Motionless and report-only candidates must be rejected with their specific reasons, and the positive control must be accepted. No success rate, latency or physical claim is made.
- **Reproduction:** `python -m pip install -r requirements-dev.txt && python -m pip install --no-deps -e .` once, then `make check` offline. Only this feature: `python -m pytest tests/test_baseline.py`.
- **Raw evidence destination:** `make baseline-evidence` runs the same suite and writes each frozen case's canonical bundle to `build/evidence/baseline/<case_id>.json`, plus `manifest.json` with the SHA-256 of every bundle, its head checksum, outcome, state, status and correctness failures, and the SHA-256 of the case, skill and candidate files. `build/` is git-ignored. Bundles are never committed; retained copies belong in an access-controlled store referenced by these hashes. Without that target, the suite writes only to pytest temporary directories.

## Implemented

**One case, end to end (`run_fixture_case`).** `plan_case` pins every eligible validated skill of one registry snapshot for the run, so later registry changes cannot alter it. `_Driver` then loops over attempts inside `BoundedRun`:

1. **Observation.** The attempt-starting `observe` is a world tool call. The observation is recorded by identity and content digest. A missing, malformed or stale (older than 200 ms) observation ends the attempt as `missing_observation`.
2. **Eligibility.** The snapshot's contract 1.0 `eligible_skills` view, computed for that observation, is intersected with the pins and filtered by each skill's `required_observations`. Only that list, and in a development trial the one declared candidate, is offered to the selector.
3. **Rule-based selection.** `RuleSelector` (`rule-selector-v1`, recorded under the `planner` role) places with `place-box` when the gripper holds the box and otherwise picks with `pick-box` at grasp height `target_pose.z_m`. It abstains when the skill it needs is not eligible. Each decision is recorded. Unsupported actions, skills outside the offered set, skills without a hand-authored body, non-integer or unknown versions, and parameters outside the skill's input contract stop the run as `failed` (`invalid_decision`) before any actuation.
4. **Bounded execution.** Hand-authored bodies (`pick_box`, `place_box`, `pick_and_place`) run as trusted host code with a `SkillContext` that allows only permitted tools. Every world call goes through `BoundedRun` (steps, attempts, wall time, output bytes) and is recorded with its result. Outputs are checked against the skill's output contract.
5. **Retries.** A failed or rejected pick/place, a stale observation or an unfinished settling window ends the attempt. A failure in the skill's `stop_on` ends the case as `blocked`. Any other failure starts a new attempt from the state actually reached. A fourth attempt is refused as `budget_exhausted`. Goal withdrawal triggers `abort` and cancellation, with no further actuation. A worker crash fails the run.
6. **Independent verification.** `FixtureEvaluator` reads only the world's privileged state and admission log. Skill reports reach it as claims; it alone sets progress and decides completion (pose and yaw within tolerance, released, settled for 500 ms, before the deadline). After a successful place the harness observes up to `SETTLE_OBSERVES` (8) times while the evaluator checks the settling window. The primary outcome follows the protocol precedence.
7. **Final event bundle.** The evaluator's final verdict is recorded as the outcome, followed by `run_finished` with the lifecycle state, in one checksum-chained `uzumaki.events/1.0` bundle.

**Semantic replay (`replay_case`).** It re-drives the same `_Driver` logic with the recorded selector decisions and recorded tool and monitor results (`recorded_decision` mode). No world, evaluator or selector runs. Changed skill or selector versions are refused (`version_mismatch`), and logic that asks for something unrecorded raises `ReplayDivergence`. A recorded worker crash is replayed as the same crash.

**Development trials.** `plan_case(..., candidate=(id, version), bodies=...)` admits one registered `candidate` or `validated` skill that applies to `pick-place-v1`, verifies, resolves its validated dependencies and has a hand-authored body. `TrialSelector` always selects it. `FixtureEvaluator.candidate_verdict` accepts it only when the case completed with zero violations and the candidate's own invocations caused real world effects. When the skill declares expected progress, a report claiming an effect that did not happen gives `success_report_without_progress`, and invocations with no effect give `no_actual_progress`. Trials never change registry state.

**Evidence export.** `export_evidence(runs, directory)` writes each bundle with `write_bundle` (validated, canonical, never overwriting) and returns the SHA-256 of each file.

## Tests (`tests/test_baseline.py`)

- Every frozen case passes every correctness check. Its recorded outcome and terminal state match the expectations, with zero model calls and zero violations.
- Per failure path, the exact world tool sequence and stop detail: unreachable target (`blocked` after a rejected place), failed grasp (second attempt completes), stale observation before and after the pick, retry exhaustion (three misgrasps, `attempts`), cancellation (`abort`, then `cancelled`) and worker crash (crashed call never reaches the world, `worker_failure`).
- The nominal bundle records the whole loop: 11 world steps, of which 9 are observes, each producing one recorded observation; both rule decisions and their parameters, skill attribution of `pick` and `place`, the monitor events, the evaluator verdict as the last tool result, and evaluator-sourced progress.
- Replay of every case matches a fresh execution, with the world, evaluator and rule selector patched to fail if used. Two fresh executions produce identical bundles. Divergent skill logic raises `ReplayDivergence`, a changed registry is `version_mismatch` and an edited bundle is `corrupt`.
- Invalid selector decisions (six kinds) fail the run before actuation. An abstaining selector stops as `abstained`. A deprecated `place-box` leaves the selector without an eligible placing skill, so the run stops as `partial_progress`. A body asking for a tool outside its permissions never reaches the world.
- Trials: `hold-still` is rejected as `no_actual_progress` and `report-success` as `success_report_without_progress`. Both make zero admitted actuations and exhaust the attempt budget. `report-success` is still rejected when the rule selector completes the case after it. The positive control is accepted. Trial bundles replay to the same outcome.
- A world-level check rejects a pick on a superseded observation without effect. The correctness checker flags a deliberately wrong expectation. Exported bundles reload, match their hashes and are never overwritten.

## Limitations

- The world is a scripted fixture: kinematics are exact, there is no contact or collision model (`collision` cannot occur), and all timings are fixture constants, not measurements. Nothing here is evidence of simulator, physical, held-out or live-model behavior.
- Skill bodies and the selector are trusted host code, not generated candidates, so they do not run in the restricted worker. A crash is injected at the tool executor, not produced by a real worker process.
- Replay is recorded-decision replay of harness logic. It does not resimulate the world or re-evaluate a model.
- The candidate verdict is a development-trial signal for the fixture cases only. It is not promotion (feature 17) and uses no held-out cases.
- `make baseline-evidence` writes local files only; uploading and access control of retained bundles are outside this repository.
