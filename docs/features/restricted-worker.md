# Restricted worker for generated candidates (issue 06)

Status: implemented as an offline library (`uzumaki.sandbox`, `uzumaki.broker`). No harness loop, skill registry, simulator or live model uses it yet. Acceptance depends on an independent, credential-free run of the adversarial suite on an admitted host; this note does not claim that run passed.

## Frozen plan

- **Workload:** `RestrictedWorker.run(source, payload)` executing candidate source that defines `run(tools, payload)`, with a `pick_place_v1_broker` whose handlers are host-side recorders (`tests/test_sandbox_containment.py`). Admission and broker logic are also tested without starting a worker (`tests/test_sandbox_admission.py`, `tests/test_broker.py`).
- **Inputs and environment:** Python 3.12.12, stdlib-only runtime, the pinned `requirements-dev.txt`. The only admitted platform is Linux x86_64 with Landlock ABI 6 or later and seccomp filter support. The factory platform probe (2026-10-19, `factory-platform-preflight-20261019`) reported x86_64, kernel 6.17.0-41-generic, Landlock ABI 7, uid 1000. That probe shows availability only; it is not containment evidence.
- **Correctness guards:** the candidate's return value is untrusted data, never a task-success claim. Only declared, versioned tools reach host handlers. Rejections and failures are fixed codes; arguments are recorded by SHA-256 digest only; candidate errors are reported as an exception type name only.
- **Containment guards:** restrictions are applied by the kernel before the candidate is read, and verified by the worker (canary file unreadable, `socket()` denied, `no_new_privs` and seccomp active) before `ready` is sent. Without a valid `ready` the run is `containment_failed` and the candidate is never loaded. Watchdog, output limits and kill authority are in the host. After every run the process group is killed, the worker is reaped and `/proc` is checked for survivors (`tree_clean`).
- **Metrics/thresholds:** pass/fail only. Every test in the three files must pass. Timing assertions are generous ceilings (20 s), not latency claims.
- **Reproduction:** `python -m pip install -r requirements-dev.txt && python -m pip install --no-deps -e .` once, then offline `make containment` on an admitted host (fails, rather than skips, when the host is not admitted) and `make check`.
- **Raw evidence destination:** tests keep reports in memory and write only to pytest temporary directories. Validation logs and their hashes belong to the separate validation run, in `runs/` or `artifacts/` (git-ignored) or an access-controlled store referenced by hash, never in Git.

## Boundary

`RestrictedWorker` starts `python -I -S -B src/uzumaki/_sandbox_boot.py <config>` with `subprocess.Popen` in a new session (its own process group), with `env={"LANG": "C.UTF-8"}`, stdin from `/dev/null`, stdout and stderr on one host pipe, the scratch directory as working directory, and only the two broker pipes passed. Before reading the candidate, the bootstrap:

1. closes every other descriptor;
2. sets rlimits: `RLIMIT_CPU` (soft `cpu_seconds`, hard +1 s), `RLIMIT_AS` (`memory_bytes`), `RLIMIT_FSIZE` (`max_file_bytes`), `RLIMIT_NOFILE` (`max_open_files`), `RLIMIT_CORE` 0;
3. sets `no_new_privs`;
4. applies a Landlock domain handling every filesystem right up to ABI 5, TCP bind/connect, and the ABI 6 scopes (signals and abstract UNIX sockets). The only rules are read-only access to the interpreter's stdlib and platstdlib, `/lib`, `/lib64`, `/usr/lib`, `/usr/lib64`, `/etc/ld.so.cache` and the per-run candidate directory, plus read/write/create/remove (no symlink, no refer) in a fresh per-run scratch directory. Everything else, including `/proc`, `/etc`, `/dev`, `$HOME`, the repository and the host temp directory, is unreachable;
5. installs a seccomp filter (x86_64 audit arch only; other arches and x32 are killed or denied). It denies with `EPERM` `socket`, `socketpair`, `execve`, `execveat`, `fork`, `vfork`, `ptrace`, `process_vm_*`, `pidfd_getfd`, `setsid`, `setpgid`, `setrlimit`, `prlimit64`, `unshare`, `setns`, `chroot`, `pivot_root`, mounts and the new mount API, module and kexec calls, `reboot`, keyrings, `bpf`, `perf_event_open`, `userfaultfd`, `io_uring_*` and file-handle calls. `clone` is allowed only with `CLONE_THREAD` and no namespace flags (threads only), and `clone3` returns `ENOSYS` so libc falls back to the filtered `clone`;
6. verifies the restrictions and sends `ready` with the Landlock ABI. Any failure sends `containment_failed` with a fixed reason and exits 70 without loading the candidate.

The candidate then runs in the same process. It can use `ctypes` and raw syscalls; that is expected, because the restrictions are enforced by the kernel and Python-level checks are not part of the boundary.

**Credentials:** the environment is scrubbed (only `LANG`), `/proc` (including the parent's `environ`) and the home directory are outside the Landlock rules, and no host descriptor except the broker pipes is inherited. **Network:** `socket()` is denied by seccomp, TCP is also denied by Landlock, and `io_uring` is denied. **Processes:** no fork, spawn or exec; signals cannot leave the Landlock domain.

## Host side

- **Admission:** `probe_platform()` reads the OS, machine, kernel, Landlock ABI and seccomp support without side effects. `admit()` refuses anything but `VERIFIED_PLATFORMS = (("Linux", "x86_64"),)` with Landlock ABI ≥ 6 and seccomp, raising `ContainmentUnavailable` (`unsupported_os`, `unverified_architecture`, `landlock_abi_too_old`, `seccomp_unavailable`) before any process starts.
- **Protected paths:** `protected_paths` (evaluator, prompts, skills, held-out assets, credentials) must not overlap the work directory or any read path, or the run is refused with `protected_path_exposed`. Their names are never sent to the worker. Because Landlock is an allowlist, anything outside the listed paths is unreachable whether or not it is declared protected.
- **Watchdog and kill authority:** a host timer kills the whole process group at `wall_ms`; the host loop also enforces the deadline. Output is read up to `max_output_bytes` and the group is killed on overflow. Broker messages are bounded by `max_message_bytes`, tool calls by `max_tool_calls`, and handled strictly request/response so a worker that never reads cannot grow host memory. The host kills the group before reaping (the unreaped PID keeps the group ID from being reused), reaps with `wait4`, then sweeps `/proc` and reports `tree_clean`.
- **Statuses:** `returned`, `candidate_error`, `timeout`, `cpu_limit`, `output_limit`, `protocol_violation`, `tool_budget_exhausted`, `crashed`, `containment_failed`. `WorkerReport` also records exit code or signal, tool-call records, bounded output, wall and CPU time, the Landlock ABI, the platform report, limits, `sandbox_version` (`uzumaki.sandbox/1.0`) and the broker manifest.

## Broker

`uzumaki.broker.ToolBroker` (protocol `uzumaki.broker/1.0`) holds a manifest of `ToolSpec(name, version, handler)` with a `manifest_version`. Handlers are trusted host adapters and run in the host. A request is rejected without calling a handler when it is malformed, names an undeclared tool or has a different version. A handler exception, a non-object, non-JSON or oversized result is `failed` with a fixed code. `pick_place_v1_broker` only accepts handlers for the `pick-place-v1` profile tools (`observe`, `pick`, `place`, `abort`, version `1.0`). There is no tool for files, the evaluator, prompts, skills, the registry or held-out data, so the candidate cannot reach them through the broker either.

## Tests

- `tests/test_sandbox_admission.py` (any host): unsupported OS, architecture, old Landlock ABI and missing seccomp fail admission without starting a process; protected paths overlapping the work root, system libraries, stdlib or `/` are refused and the work directory is removed; invalid limits and inputs are refused; host and bootstrap agree on the minimum ABI.
- `tests/test_broker.py` (any host): undeclared tools, version mismatches and malformed requests never reach a handler; failing handlers become fixed codes without leaking details; records keep digests, not raw arguments; invalid manifests are refused.
- `tests/test_sandbox_containment.py` (admitted hosts only, real processes and clock): declared tools reach host handlers and threads and scratch I/O work; undeclared tools and wrong versions never reach the host. Adversarial fixtures: **file escape** (reading, writing, listing, deleting, renaming, hard- and symlinking evaluator/prompts/skills/held-out assets, path traversal, the repository, `/etc/passwd`, `/proc/self`, `/dev/mem`, the host temp directory, the candidate file and the bootstrap); **credentials** (environment, `~/.aws/credentials`, parent and own `/proc/*/environ`, `~/.ssh`); **network** (TCP to a host listener, UDP, IPv6, UNIX socket to a host listener, netlink, socketpair, raw `socket` syscall, `io_uring_setup`); **subprocess and privilege escape** (`subprocess`, `os.system`, fork, `posix_spawn`, exec, `setsid`, `setpgid`, killing a host process, signalling the parent and init, raising rlimits, user namespaces, `ptrace`); **hangs** (busy and sleeping loops ignoring `SIGTERM`/`SIGXCPU`, killed by the host watchdog while a host thread keeps ticking, then a new run succeeds); **CPU limit**; **memory exhaustion** (single and gradual); **output flooding** (stdout, stdout loop, stderr loop) and a scratch file flood; **broker abuse** (non-JSON, non-object, second `ready`, oversized message, tool budget); **crashes** (`_exit`, `abort`, segfault) reaped with the host still usable; error reporting by type only; Python-level tricks (reloading modules, libc `open`, `prctl` to disable seccomp, restored builtins); and a misconfigured bootstrap that fails closed on a reachable canary without loading the candidate. A fixture asserts that no process of any worker group survives any test.

On a host that fails admission, `tests/test_sandbox_containment.py` is skipped with the admission reason (shown by `pytest -ra`). A skip is not a pass; `make containment` turns it into a failure.

## Limitations

- **Tested platform:** none is claimed here. Linux x86_64 with Landlock ABI ≥ 6 is the only admitted target, and the factory probe above shows such a kernel exists in the factory environment. Whether the containment suite passes there is established only by the separate credential-free validation run, which records the exact checks, exit status and log hashes. Other OSes, aarch64, and kernels before 6.12 (Landlock ABI < 6) fail admission. Containers or seccomp policies that block Landlock or nested seccomp also fail admission or fail closed.
- **Hosts without network:** some validation hosts run the whole test process under an inherited seccomp network guard, so the host cannot create the TCP and UNIX listeners used as bait. The network test then still makes every candidate attempt and requires each to be denied (target port 9 instead of a listener), but it cannot check that nothing reached a host listener. On such a host, the worker's network denial cannot be attributed to its own filter alone, because the inherited guard also denies `socket()` with `EPERM`. The test does not skip in that case.
- **CI:** GitHub-hosted `ubuntu-latest` runners may report a Landlock ABI below 6, in which case `make check` skips the containment suite there. CI therefore does not by itself evidence containment.
- **Shared resources:** the worker runs as the host's user, in the host's PID, network, IPC and mount namespaces (no namespaces or cgroups are used). Landlock and seccomp block it from acting on them, but it can observe host-visible system state allowed by the syscall deny-list (for example the time, `uname`, its own PID). Memory is bounded by `RLIMIT_AS` per worker, not by a cgroup; scratch disk use is bounded per file (`RLIMIT_FSIZE`) and file count (`RLIMIT_NOFILE`), not in total. Thread count is not limited beyond memory and the wall/CPU deadline.
- **Seccomp is a deny-list** for the verified x86_64 ABI. A syscall added in a later kernel is allowed unless Landlock covers it; new kernels should be re-validated before being trusted.
- **System libraries are readable** (`/lib`, `/usr/lib` and the stdlib), so they must never hold secrets or protected assets; `protected_paths` overlapping them are refused.
- **`tree_clean`** is checked by process group from `/proc`. Fork, exec, `setsid` and `setpgid` are denied, so a worker cannot leave its group; the sweep is a verification, not the containment.
- The worker is not a physical safety controller, and broker handlers are trusted host code: their own safety is the adapter's responsibility. Broker answers and the candidate's result are untrusted data; only the future independent evaluator decides task success.
- `uzumaki.deadline` (issue 05) is unchanged and remains a process-bounding helper, not a sandbox.
- Results of `make check` and `make containment` come from CI or a separate validation run; they are not asserted here.
